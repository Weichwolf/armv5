# ISA and implementation coverage

A1–A5 qualify the functional ARM926EJ-S ARMv5TEJ profile below on Linux x86-64.
Jazelle uses the architecture's trivial implementation; Java bytecode execution
is unavailable. Cache controls are functional, without stored cache contents or
bus timing. CP14 debug registers use the disabled-debug profile choice below.
Tests are independently authored programs, run through the public interface with
installed images. Rejected preparation cannot produce an installed image and is
checked through `Core::lower`; no private decoder or alternate executor is used.

Qualification covers operation classes, addressing families, architectural modes
and numeric boundaries through the fixtures named above. It does not claim an
exhaustive encoding/operand Cartesian sweep. Reserved/unpredictable cases and
electrical test/debug operations outside the declared profile refuse explicitly.
No external coprocessor, Java engine, JTAG/DCC handshake, stored cache content,
write-buffer queue or cycle-accurate bus is modeled.

CP14 debug profile choice: privileged ordinary MRC/MCR, opcode_1=0,
CRn=0..2, CRm=0, opcode_2=0 read zero and ignore writes. User access takes
Undefined. ARM9E-S DDI 0165B section 7.8 describes a real communications channel
whose W flag sets after a write; this profile deliberately leaves W zero, even
after a write, without a debugger or channel state. This is an explicit
functional-profile deviation, not a hardware DCC model.

Instruction encodings/semantics: ARM DDI 0100I A2–A7, restricted to ARMv5TEJ.
Profile: DDI 0198E. Nominal cycle accounting: DDI 0165B 8.1, without interlocks or
bus waits. References and their exact local identities are in
`reference-manifest.json`; manuals never enter production builds or tests.
